# Whole-app review, 31 October 2026 (HA-32)

A read-through of the whole repository (server, UI, Electron shell, scripts, CI and docs) plus a runtime pass
on test servers: screenshots of every view at desktop and phone sizes, malformed requests against the API,
concurrent task creation, deleting one of two projects on one repository, and the browser test suite.

Eight reviewers each took an area and reported findings with a concrete failure scenario; the ones below were
then confirmed by reading the code or reproducing them. Findings fixed in the pull request for HA-32 are marked
**fixed**; the rest are follow-up tasks on the board (named where one exists) or notes.

## Overall

The codebase is in good shape. The things that are hard to get right are right: the public/authenticated
split of the API, SQL that is whitelisted and bound, path handling for attachments and documents, the merge
queue and "merged" detection, the agent run lifecycle (steering, restart recovery, MCP idempotency), the broker's
windowed streams, and the UI's handling of out-of-order loads and host id collisions. The browser test suite
(140 tests) and the server suite (410 tests) passed on master before any change.

What recurs across areas:

- **Loose typing at the edges.** PATCH handlers copy raw JSON into whitelisted columns, and SQLite keeps a value of
  the wrong type as it is, so one bad field could make a row unreadable (the worst case: every task list of a
  project returning 500). Settings and profile updates treated a non-string as "clear".
- **Errors that go nowhere.** Several UI actions (delete task, model/effort/title edits, destructive settings
  actions) didn't surface failures; a few flows swallowed them and navigated away as if they had worked.
- **Hygiene around secrets and paths.** Token comparisons weren't constant-time, token files were briefly
  world-readable, the hub forwarded its own token to linked hosts, terminals inherited the broker token, and
  worktree setup adopted any folder at its path (with a forced teardown then removing it).
- **Trust boundaries that are softer than they look.** The broker's single shared token lets a connected host
  take over another host's name; `create_project` is pre-approved for any path on the host; agents' MCP helper
  carries the host's full token, so profile scoping is organisational, not a security boundary.

## Fixed in this pull request

Server:

- `PATCH /tasks/{id}` checks `title` (non-blank string), `description` (string or null), `position` (number),
  `use_worktree` (boolean), `model` and `base_branch` (string or null). Before, `{"position": "top"}` stored text in
  a REAL column and every list containing the task returned 500 until the row was repaired by hand; `{"title": null}`
  was a 500; `{"title": {"a": 1}}` was kept as JSON text. Regression test: `a_tasks_fields_are_checked_for_type_before_theyre_stored`.
- `PATCH /settings` refuses non-string, non-null values instead of clearing the setting. Test:
  `a_setting_of_the_wrong_type_is_refused_rather_than_cleared`.
- Worktree setup no longer adopts a folder at the worktree's path unless git lists it as a worktree of the
  repository, and a forced teardown only removes a folder by hand when it's inside the project's worktrees folder
  and isn't a main checkout. Test: `a_folder_in_the_worktrees_way_is_neither_adopted_nor_removed`.
- The access token and hub token are compared in constant time (`util::same_secret`, which the webhook path already
  used); token files are created with mode 0600 rather than chmod'ed after writing.
- The hub strips `?token=` from proxied HTTP requests as it already did for websockets, and an outbound link sends
  its token as a header rather than in the websocket URL (which proxies and brokers log).
- Terminal shells no longer inherit `IA_BROKER_TOKEN`.
- `git_push` accepts a branch name only (no refspecs such as `+HEAD:refs/heads/master`). Test in `gh_mcp`.
- The MCP helper fails fast on a 4xx other than 408/429 instead of retrying for 30 minutes (a stale token, say).
- Codex agents get the same note as Claude agents about which profiles' boards they can't use (README promised it
  for both).
- Indexes on `runs(task_id, created_at)` and `permission_requests(task_id, status)` (migration 63): the idle-session
  sweep every minute and the pending-prompt count on every task read were full scans of tables that only grow.

UI:

- A card dropped on its own top half stays put; it went to the end of the column with a position update. Browser
  test: `selfDrop.test.mjs`.
- Details → Status → "In progress" starts a fresh task's agent, as dropping it on the board does. Checked on a
  test server with the fake agent.
- Delete task shows a failure and keeps the dialog open instead of closing as if it had worked (landed first in
  HA-40's shared ConfirmModal; the browser test `deleteTask.test.mjs` from this review covers it).
- Context menus no longer close on the next streamed token (the thread scrolling itself fired the global scroll
  listener that closes them).
- A 401 from a linked host no longer signs the user out of the whole board (`unauthorizedHere`; unit test in
  `router.test.mjs`).
- A path with a malformed escape (`/g/h/100%`) no longer crashes the app at render (no error boundary catches it).
- Electron: `window.open` only hands http(s) and mailto URLs to the OS (plans and artifacts are agent-written pages
  whose scripts can open popups; `file:` and custom schemes stayed reachable), and a `will-navigate` guard keeps a
  file dropped outside a drop zone from replacing the board.

Tooling and docs:

- `rust-version = "1.89"` in the three Cargo.toml files, and the install script and README say 1.89 (the locked
  `uuid` needs it; the old 1.85 check passed and the build then failed a minute later).
- `scripts/test-server.sh` scrubs every `IA_*` variable the server reads (broker, profiles, source dir, update-from),
  so a test server started under a daemon that has them can't register on the real broker or rebuild the live checkout.
- `scripts/copy-live-board.sh` disables automations and PR polling in the copy.
- CI also runs on pushes to master; `app/package.json` declares `engines.node`; README names both UI test commands
  and the `--token` flag and `ui-check.mjs`.

Security and trust:

1. **Broker: one shared token is a key to every host.** Any client with the broker token can `Hello` as another
   host's name; the broker replaces the holder and routes the victim's traffic (including the browser's host
   token) to the impostor. Bind names to the `host_id` that registered them or use per-host secrets, and reword
   README's description of the broker token. (`server/broker/src/lib.rs` around the name insert.)
2. **`create_project` is pre-approved for any host path** while `update_project`'s `repo_path` needs approval. A
   prompt-injected agent can register `$HOME` as a project and start a task there in the default mode. Route it
   through `permissions::approve` or confine it to the profile's clone folder. (`server/src/tools.rs`.)
3. **Agents hold the host's full token**, so profile scoping in the tools is a convenience boundary. Either
   per-run scoped tokens checked by `auth`, or say so in the docs.
4. Generic `gh` tool: deny `auth` (`gh auth token` puts the account's token in the thread), `extension`,
   `alias set`, `config set`. Setup/teardown scripts have no time limit (status scripts do). `admin/update`'s
   `commit` and `ssh-host`'s target reach argv unvalidated (token holders only; fragility rather than escalation).
5. `release.yml` grants `contents: write` to its pull-request runs; restructure so only release/dispatch runs
   have it.

Reliability:

6. **Hub links have no keepalive.** A half-open connection (NAT timeout, laptop sleep) leaves a host "connected"
   and every proxied request waits 300 s; the host's own loop never notices. The broker and SSH modes have pings.
   Add ping/idle timeouts to `run_outbound`, `serve_tunnel`, `tunnel_to` and connect timeouts. Related:
   `spawn_outbound` aborts the old task without unregistering its `LinkConn`; duplicate names/ids make hosts
   replace each other in a loop; a host linked both ways loses its outbound mode after a hub restart.
7. **`DELETE /profiles/{id}` skips the cleanup** project and task deletion do: worktrees stay registered, terminals
   and document folders stay, prompts aren't expired, and an unknown id answers 200.
8. **`loadProfiles` has no ordering guard** in the UI store (refreshHost does): a stale profile list applied after
   a newer one drops the newer profile's tasks until the next change. Number it like `refreshes`.
9. **Hosts page: the Update spinner can stick forever** (it compares the host's commit with the hub's running
   commit, but the update sends the checkout's HEAD; the restart record is in-memory and gone after restart).
10. Ghost agents: `execute_mcp` serves calls from runs the board already finished (shim died, agent alive), and
    `load_active` can leave a run idle with its input open after a crash between `record_result` and `turn_ended`.
11. Worktree settings aren't validated: a relative `worktrees_root` lands worktrees inside the main checkout;
    `base_branch` isn't checked with `check-ref-format`; teardown doesn't check for a running reviewer in the
    worktree; untracked files are listed without `-z`, so non-ASCII names drop out of the branch diff.
12. `update_task_inner` checks state without a lock before writing (two simultaneous moves to Ready for merge,
    or a run starting between the check and the write); task creation isn't transactional (a failed insert burns a
    key number). Profile names aren't unique, but access grants are by name.
13. `disk::plan` does filesystem I/O under the database lock; `GET /tasks/{id}/document` and a few delete/keepalive
    routes don't 404 on unknown ids; `/api/hosts/join` builds the dial-in command from the Host header, which is
    wrong through a broker.
14. Webhooks: the rate limit counts unsigned junk (anyone with the URL can starve real deliveries), and a signed
    delivery can be replayed with its delivery id header stripped.
15. Changes tab acts on `--show-toplevel` of the project folder: a project inside a bigger repository (a home
    directory that is a dotfiles repo) stages or resets the enclosing repository.
16. Moving a task to Ready for merge on a host that can't run agents leaves `merging=false`, so it never joins the
    queue once agents are available. `ia-api` can't resolve `S-`/`G-` keys and still queries a `scratch` kind.

UI and UX:

17. **Streaming re-parses the whole reply as Markdown on every token**, and every token is a store-wide `setState`
    that re-runs every mounted selector; the board also recomputes columns and progress maps on every task event.
    Coalesce deltas per frame, render the live tail as plain text, keep deltas out of the main store. Measure with
    `scripts/ui-profile.mjs`.
18. **Destructive settings actions are fire-and-forget** (remove host, delete profile, delete project, rename host):
    failures are silent and double-clicks repeat them. One `useAsyncAction` with busy and error, and a shared
    `ConfirmModal` to replace the ten `window.confirm` calls.
19. Details inputs overwrite typing when the field changes under them (an agent setting `pr_url` while the user
    pastes one); model/effort/title/unpin writes have no error path; Rename host and the automations' public
    address field are seeded once and can undo another board's change.
20. Triage's "Ready for your review" disagrees with the sidebar's count (it ignores a running reviewer); the Live
    view says "Reply to the agent" on tasks with no agent; the phone layout's tab row scrolls so the Start button is
    half off-screen; the plan's "questions answered" bar overlays document text.
21. Accessibility: `Toggle` has no switch semantics; attached files can't be removed on touch or by keyboard
    (hover-only button); Shift+Tab is trapped in the composer; backdrop mousedown discards dialogs with unsaved
    input; switching tasks can open the new thread at the previous task's scroll offset.
22. Electron: the startup error page hides the server's stderr; a 1 s health probe can start a second server beside
    a slow one; if the spawned server exits later the window goes dead; `allow-modals` lets agent HTML show
    native dialogs under the app's name; the first render waits on a request for the open token on every load
    (needed only on previews; a stored token could render at once and refresh the open token behind it).
23. Board.tsx is 2500 lines (NewTaskModal and TaskBoard about 1000 and 900); TaskCard and TaskRow repeat the same
    badge row; three near-identical drop handlers. Analytics and Document each have their own `download()`.

CI and tooling:

24. **The 37 browser test files and the Vite build never run in CI**; neither does `scripts/ia-api-test.py`. Add a
    `ui` job (debug server build, Chromium, `npm run test:ui`) with a `CHROMIUM` override in `ui-check.mjs`.
25. Dependencies: `tokio-tungstenite 0.30` and `tower-http 0.7` duplicate axum's 0.29 and reqwest's 0.6 stacks.
    `test-server.sh --seed` needs jq and curl silently; `install.sh` runs top-level code under `curl | bash` (wrap
    in `main`).
26. Docs: README's Rust floor and test command (fixed here); `IA_FAKE_CLAUDE_TITLE` undocumented; the README says
    nothing about the broker token's reach (see 1).

## Checked and sound

So nobody re-reviews them: only `/api/health`, `/api/hub/connect` (hub token), the webhook route (constant-time
token, body cap, rate limit) and `--open-token`'s route are reachable without the bearer token, and the hub proxy
can't reach `open-token` or recurse; attachments need a hex id and a clean name; the UI is served by `ServeDir`;
every dynamic UPDATE goes through a column whitelist; task numbering is atomic (12 concurrent creates got 12
distinct numbers); `DbGuard` is `!Send`, so a guard can't be held across an await; lock order is runs → db
everywhere; the broker refuses `open-token` through path normalisation with tests for `%2e`, `\`, `//` and
double-encoding; markdown goes through react-markdown without raw HTML and with a safe URL list; `pr_url`,
`preview_url` and external links are http(s) server-side; the document frame has no `allow-same-origin`, checks
`e.source`, and Mermaid runs with `securityLevel: strict`; Approvals bind decisions to request ids; plan answers
are keyed per host and task; polling intervals are cleared on unmount; deleting one of two projects on the same
repository removes only its own worktree and keeps the other's uncommitted file.
