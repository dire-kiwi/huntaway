# The Vite+ monorepo restructure, 6 November 2026 (HA-263)

HA-263 restructured the repository as a pnpm workspace with Vite+ as its toolchain, moved the tests onto Vitest,
formatted the code with Oxfmt and rewrote the README. It changed no behaviour on purpose: the issues it came across are
listed here, not fixed (see *Issues found*). [development.md](../development.md) describes the result.

## What changed

- **Layout.** `server-ts/` → `apps/server`, `app/` → `apps/web`, `mobile/` → `apps/mobile`, `server/{shim,broker}` →
  `rust/`, and the Cargo workspace (`Cargo.toml`, `Cargo.lock`, `.cargo/`) to the root. `packages/client` stayed. The
  first commit is renames only, so that other branches' changes follow the files.
- **pnpm.** One `pnpm-lock.yaml` for the workspace in place of three `package-lock.json` files; `@huntaway/client` is
  linked with `workspace:*`. The lockfile has `master`'s versions of every direct dependency. pnpm had re-resolved 13
  of them within their ranges; transitive dependencies were re-resolved. The mobile app had been using three packages it
  didn't declare (`@types/node`, `@expo/config-plugins`, `@expo/prebuild-config`, which npm's hoisting gave it), and
  declares them now. Its Metro config is Expo's default, which handles monorepos.
- **Vite+.** `vite-plus` 1.5.0 (Vite 8.3.5, Vitest 5.1, Oxlint, Oxfmt, tsgolint), set up in the root's
  `vite.config.ts`. Type checks moved from tsrs (`tsrs -b`, `tsrs -p`) to Vite+'s (`vp check`), which checked the same
  files: a type error planted in each package was reported, `noUnusedLocals` included. The server keeps tsrs for release
  packages and its floating-promises check.
- **Vitest.** The server's 1329 tests, the web app's 229 and its 247 browser checks run on Vitest in place of node:test
  (a codemod: hooks renamed, `t.after` → `onTestFinished`, `mock.timers` → `vi`'s fake timers). The suites take about
  half as long: 30 s for the server's and web app's together, and 49 s for the browser checks, 8 files at a time. The
  mobile app stayed on Jest.
- **The server.** Its test-process checks (`NODE_TEST_CONTEXT`, and `--test` in `execArgv` in four modules) became one
  `IN_TEST` (`util.ts`). Rebuild & restart installs with pnpm and builds ia-shim at the root, and no longer needs
  `lockfile_changed`. `package-server.sh` takes the production dependencies from `pnpm deploy`; a release package's layout
  didn't change.
- **Old paths.** `server-ts/bin/*` and `app/` forward to the new layout (see *The layout before HA-263* in
  development.md).
- **CI.** `test.yml` sets up with Vite+'s `setup-vp` and runs `check`, `server`, `web`, `mobile`, `ui (n/3)` and `rust`;
  `release.yml` builds with pnpm.
- **Docs.** The README went from 222 KB to a page; its reference moved, as it was, into ten guides in `docs/guide/`, and
  dated notes like this one into `docs/notes/`. CLAUDE.md, the server's README and PORTING.md, structure.md and the
  pointers in the UI and server that named README sections follow.
- **Formatting.** Oxfmt formatted every TypeScript, JavaScript, JSON and Markdown file (lines of up to 160 characters;
  test fixtures left as they were) in one commit of its own, which `.git-blame-ignore-revs` lists.

## Verified

- Every suite above, on the new layout, before and after the format; `vp check`; `cargo test`.
- A release package from `scripts/package-server.sh`: `--version`, `issue-agent`, and a server that starts and serves
  the API and UI.
- **A checkout updating across the move:** a server from `master` in a scratch clone whose checkout was then
  fast-forwarded onto this branch. Its Rebuild & restart (the old code: `npm` in `app/`, `cargo` in `server/`) built
  the new layout through `app/package.json` and restarted onto the new server through `server-ts/bin/huntaway`, which
  found its checkout. A second Rebuild & restart, now the new code, restarted onto `apps/server/bin/huntaway`.

## Not verified

- The Android APK: `release.yml` builds it with `expo prebuild` and Gradle only when a release is published, so pnpm's
  layout under React Native's Gradle build hasn't run. The Jest tests and the type check pass. Likewise the desktop
  packages (`electron-builder`) are built only by `release.yml`. The release package of the server and the UI build
  were checked by hand, as above.
- The desktop app run from a checkout, and an older `install.sh` launcher starting it through `app/`. The path that
  launcher takes (`app/package.json`'s `main`) was checked to resolve, not run.
- The PR preview and the hub's deployment, which are built in huntaway-deploy from `app/dist` and `server/`. They need
  that repository's scripts changed (a follow-up there).

## Issues found

Most likely to matter first.

1. **A browser check passes by accident.** `narrowLayout.test.mjs`'s "on a phone a task's Start button is on screen"
   clicks *Edit this task's title and description*, which the test before it moved to *In review*, so the card it clicks
   is in a column off screen (inert). Playwright 1.64 clicks it anyway; 1.65 refuses, and the check fails. The lockfile
   keeps 1.64.1, so it passes, but updating Playwright needs the test fixed first (it should start from a task that's in
   *To do*, rather than depend on the order the file's tests run in).
2. **huntaway-deploy's hub build is out of date.** `hub/build.sh` and `hub/bundle.sh` (as the checkout on this machine
   has them) build `server/` with cargo and copy `server/target/release/huntaway`, the Rust server HA-179 removed, as
   well as `app/dist`. Whatever builds previews now, it has to follow the new layout: `pnpm install`,
   `pnpm --filter huntaway-app build` (`apps/web/dist`), `cargo build --release -p ia-shim` (`target/`), and
   `scripts/package-server.sh` for the server.
3. **The forwarders are temporary.** `app/`, `server-ts/` and `scripts/legacy-update.sh` should go once every checkout
   that updates itself has run Rebuild & restart past HA-263 (and `install.sh` has run again where it installed a
   desktop app). Until then, an old launcher logs "couldn't stamp the app's frame" on start (main.cjs stamps
   `app.getAppPath()`, which is `app/`), which only matters for deciding whether to relaunch after an update.
4. **`huntaway serve --help` fails** ("unexpected argument '--help'"): there's no list of the options short of the
   guide's table (*Server options* in docs/guide/server.md).
5. **Lint backlog.** `vp lint` (Oxlint, with type-aware rules) reports about 300 warnings and no errors. The ones read
   in the server's own code were all harmless: the six floating promises it reports are calls to functions that end in
   `.catch` (`const check = () => p.catch(…); check()`), which the server's own check
   (`tests/floating_promises.test.ts`) understands and Oxlint's rule doesn't, so that check stays; two `await`s of
   values that aren't promises (`agent/title.ts:90`, `hosts/ssh.ts:237`) are harmless; `cond && f()` statements
   (`hosts/hub.ts:567`, `agent/title.ts:333`) are style. By rule: `no-floating-promises` 86 (58 in the web app, mostly
   its browser checks), `no-redundant-type-constituents` 41 (`any` in unions), `restrict-template-expressions` 32,
   `no-misused-spread` 27 (spreading strings into code points, deliberate where it's done), `require-array-sort-compare`
   22, `no-useless-spread` 21, `no-meaningless-void-operator` 15, `no-base-to-string` 10, `prefer-string-starts-ends-with`
   9, and a few each of the rest. Two number literals in `hosts/broker/proto.test.ts` lose precision as doubles
   (`no-loss-of-precision`), which a test of 64-bit fields may not mean.
6. **Leftovers from the Rust server.** `apps/web/electron/main.cjs` and `scripts/install.sh` (`has_build`) still look for
   a Rust build in `server/target/release/huntaway`, for checkouts that hadn't installed the TypeScript server's
   dependencies since HA-179, and `scripts/ram-compare.mjs` compares a Rust build with the TypeScript server. All three
   can probably go.
7. **Noise in test output.** The server's tests print `MaxListenersExceededWarning` (11 `close` listeners on a
   `ServerResponse` and a `ClientRequest`), which may be a listener added per request somewhere in the HTTP or proxy
   code; Node 26 prints a `module.register()` deprecation from Vite+'s loader and a `localStorage` warning in the web
   app's tests; pnpm 10.34 prints "Ignored build scripts" for the two packages `allowBuilds` turns off.
8. **Cross-references by name.** The guides refer to each other's sections in italics (*Hosts*, *GitHub accounts*), as
   the README did within itself; across files they'd be better as links. The README referred to a *Release updates*
   section that didn't exist (so did `install-release-host.sh`); they point at *Updating the desktop app* now.
